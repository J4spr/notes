# Summary of SQL PowerPoint Slides

Here is a summary of the concepts covered in the provided presentation files.

## 1. Indices, Correlated Subqueries, and DML
*(File: 10_Indices_corr_subqueries_DML_Subquery.pdf)*

* **Indices**:
    * **Purpose**: Speed up data retrieval by avoiding full table scans (similar to a book index).
    * **Structure**: Uses B-Trees (Balanced Trees) to point to the physical location (CTID) of data.
    * **Management**: Created via `CREATE INDEX` and removed via `DROP INDEX`.
    * **Analysis**: Use `EXPLAIN ANALYZE` to check if a query uses an Index Scan or Sequential Scan.
    * **Best Practices**: Index columns used in `WHERE` and `JOIN` clauses. Avoid indexing small tables, frequently updated tables, or columns with low cardinality (few unique values).
* **Correlated Subqueries**:
    * Subqueries that execute once for *each row* of the outer query.
    * Often use `EXISTS` or `NOT EXISTS` operators to handle availability checks (and NULLs) better than `IN`.
* **DML with Subqueries**:
    * **INSERT**: `INSERT INTO ... SELECT ...` to copy data.
    * **UPDATE**: Use subqueries in `SET` (to calculate values) or `WHERE` (to filter rows).
    * **DELETE**: Use subqueries in `WHERE` to determine which rows to remove.

## 2. Subqueries and Views
*(File: 09_Subqueries_and_views.pdf)*

* **Subqueries**:
    * **Single-row**: Return one row; use operators like `=`, `<`, `>`.
    * **Multi-row**: Return multiple rows; use operators like `IN`, `ANY`, `ALL`.
* **Views**:
    * **Definition**: Virtual tables based on a stored `SELECT` query.
    * **Benefits**: Simplify complex queries, restrict data access (security), and present independent data formatting.
    * **Modifying Data**: Simple views (1 table, no aggregates) are usually updatable. Complex views (joins, aggregates, `DISTINCT`) are generally read-only unless triggers are used.

## 3. Set Operators and Conditional Functions
*(File: 08 - Set operatoren_conditionele functies.pdf)*

* **Set Operators**: Combine results from multiple queries (must have same column count/types).
    * `UNION`: Combines results, removes duplicates.
    * `UNION ALL`: Combines results, keeps duplicates.
    * `INTERSECT`: Returns rows present in *both* queries.
    * `EXCEPT`: Returns rows in the first query but *not* the second.
* **Conditional Functions**:
    * `CASE`: If-Then-Else logic (`CASE WHEN ... THEN ... ELSE ... END`).
    * `COALESCE`: Returns the first non-null value (useful for defaults).
    * `NULLIF`: Returns NULL if two expressions are equal (useful to prevent division by zero).
    * `GREATEST` / `LEAST`: Selects the max/min from a list of values.

## 4. DDL, DML, and Identity Columns
*(File: 07_DDL_ALTER_DROP_IDENTITY_and_DML_NL.pdf)*

* **DML (Data Manipulation)**:
    * `INSERT`, `UPDATE`, `DELETE` operations.
    * Constraint violations (PK, FK) will block these operations.
* **DDL (Data Definition)**:
    * `TRUNCATE`: Removes all rows instantly (resets storage, faster than DELETE).
    * `DROP TABLE`: Deletes table and data (`CASCADE` for dependencies).
    * `ALTER TABLE`: Add/drop columns, change data types, add/drop constraints.
* **Identity Columns**:
    * Modern replacement for `SERIAL` to auto-generate IDs.
    * `GENERATED ALWAYS`: Database controls values strictly.
    * `GENERATED BY DEFAULT`: Auto-generates but allows manual override.

## 5. Review: DQL (Data Query Language)
*(File: 10b_Herhalingsles_DQL.pdf)*

* **Relational Model**: Importance of Primary Keys (PK) and Foreign Keys (FK).
* **Joins**:
    * **Inner Join**: Matches only.
    * **Outer Join** (Left/Right/Full): Includes unmatched rows with NULLs.
    * **Self Join**: Hierarchies within the same table.
* **Aggregation**: `GROUP BY` organizes data; `HAVING` filters the grouped results (unlike `WHERE` which filters before grouping).
* **Subqueries**: Recap of correlated vs. uncorrelated logic.
